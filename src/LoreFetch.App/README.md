# LoreFetch.App

The Avalonia desktop app: camera preview, capture/cohort UI, collection view and the File menu (runs, export). The App domain also covers `Core/Trigger` (the `IAutoCaptureTrigger` implementation); see the [domain map](../../docs/CONTRACTS.md#domain-map).

## Dependencies

References `LoreFetch.Core` and `LoreFetch.Capture` (project references). This project is the **composition root**: it is the only place that calls `ScanPipelineFactory.Create` and `IFrameSourceFactory.CreateAsync`, both in the contract surface. It does not implement the wiring itself, and it does not reference OpenCvSharp — no contract type exposes one (see [`../../docs/CONTRACTS.md`](../../docs/CONTRACTS.md)), so the UI never writes CV code. Frames cross into the UI as `byte[]`/`CameraFrame`, converted to a single reused `WriteableBitmap`.

`CompositionMode.Real` wires the concrete `WebcamFrameSourceFactory` (Capture) — see the fixed name in [`../../docs/history/orchestration-plan.md`](../../docs/history/orchestration-plan.md) §4 — plus the real detector, rectifier and hash-index-backed identifier/catalog (Detection and Identification) and the real collection store and export adapters (Collection). `CompositionMode.Fakes` still runs entirely against `Core/Fakes` (`FolderFrameSource` and friends), with no camera, no hash index and no collection store touched.

Packages I1–I3 finished this wiring: I1 the collection store (`LoreFetch.Core.Collection.CsvCollectionStore`) and both export adapters (`LoreFetch.Core.Export.NativeCsvExporter`, `LoreFetch.Core.Export.MoxfieldCsvExporter`); I2 the detector (`LoreFetch.Core.Imaging.ContourCardDetector`), rectifier (`LoreFetch.Core.Imaging.PerspectiveRectifier`) and a single `LoreFetch.Core.Identification.HashCardIdentifier` used as both `ICardIdentifier` and `IOracleCatalog`, loaded from the committed index (`data/index/cards.lfidx`) with `ScanSettings.GoodDistance`/`OkDistance` fed from the committed `thresholds.json` — no distance literal appears in Real mode's own code; I3 the webcam frame source and the `LOREFETCH_MODE` default flip (below). `ScanSettings.CameraRotationDegrees` is set to 0 at composition for Real mode — the camera is landscape and unrotated (`docs/DECISIONS.md` "Geometry") — the contract's own default stays 90 and is unchanged.

A missing or corrupt committed index/thresholds file fails Real mode loudly: composition logs a critical error naming the path and the app exits with a non-zero code, rather than silently falling back to Fakes. A camera that simply is not attached does **not** crash — that failure is deferred to the existing `SourceFailed` banner (below), the same as a camera that disconnects mid-session.

## Stack pins and traps

Avalonia 12.1.2, `Avalonia.Controls.DataGrid` as a separate package, `CommunityToolkit.Mvvm`. ## Internals

**Composition root.** `AppComposition.CreateAsync(CompositionMode, …)` is the only place that calls `IFrameSourceFactory.CreateAsync` and `ScanPipelineFactory.Create`. `CompositionMode.Fakes` wires the seven `Core/Fakes` implementations plus this stream's own `AutoCaptureTrigger`, wrapping two of the stubs — `LayoutFollowingCardDetector` over `StubCardDetector`, `DemoCardIdentifier` over `StubCardIdentifier` (see `Fakes/` below) — so the demo actually tracks the UI's own settings instead of freezing at whatever composition set once at startup. `CompositionMode.Real` builds its own, entirely real set instead: `ContourCardDetector` wrapped in `StabilizingCardDetector` (so a card found on some frames and missed on others holds steady), `PerspectiveRectifier`, one `HashCardIdentifier.Load(…)` used as both `ICardIdentifier` and `IOracleCatalog`, `ThresholdsFile.Load(…)` feeding `ScanSettings.GoodDistance`/`OkDistance`, a `RunStore` over `CsvCollectionStore` (below), both real export adapters, and a frame source chosen by `ChooseRealFrameSourceFactory` — `LOREFETCH_FRAMES_DIR` when set (folder replay, same fallback rules as Fakes), the real webcam otherwise, wrapped in `RealWebcamFrameSourceFactory` so "no camera attached" defers to the pipeline's own `SourceFailed` event (below) instead of crashing composition before `MainWindow` exists.

**Preview path.** `MainWindow` allocates exactly one `WriteableBitmap` for the life of the window (`EnsureBitmap`), reallocated only when the frame's dimensions change. Each pipeline callback (`OnFrameProcessed`, background thread) hands its bytes to `FrameHandoff` — a three-slot rotation, not one shared buffer — because the earlier single-buffer design let the UI thread convert from a *reference* to the same array the pipeline thread could still be overwriting, tearing frames (top of one frame, bottom of the next). `FrameHandoff` makes that impossible by construction: the producer's back slot is always distinct from whatever the consumer currently holds, so a write into a slot mid-read can't happen. `OnRenderFrame` (UI thread) takes the newest slot, converts it via `PixelConvert.ToBgra32`, locks the bitmap, copies, and disposes the lock **before** calling `InvalidateVisual()` — in that order, because the Skia backend only invalidates its cached `SKImage` snapshot on the lock's `Dispose()`, not on `InvalidateVisual()` itself. Rendering is throttled to ~15 fps and coalesced to at most one outstanding request; a frame landing inside the throttle interval used to be dropped silently, which left the last frame undrawn forever if the source then stalled — it's now deferred with a timer instead, so the newest frame still reaches the screen even if nothing else arrives.

**Overlay transform.** `FrameToControlTransform` maps a `CardQuad`'s frame-coordinate corners onto `PreviewImage`'s control coordinates, accounting for `Stretch="Uniform"` letterboxing: scale by the smaller of the two axis ratios, then centre the slack on whichever axis has it. It's a pure, directly-tested function rather than inline arithmetic in the render callback — getting the min/centring wrong silently misplaces every quad without ever throwing.

**Overlay deadband.** `QuadOverlayDeadband` keeps each drawn border still until its card has really moved. A detection within 4 frame px of the drawn border at every corner leaves it in place, which absorbs the detector's corner jitter. A detection further away moves the border only after it has held for 3 rendered frames in a row, which absorbs the detector flip-flopping between two outlines a few pixels apart (seen on cards lying square to the camera). It compares against what is drawn, not the previous detection, so a slow slide still catches up. Display only: capture uses the pipeline's own quads.

**View models.** `MainViewModel` is the window's `DataContext`: it writes the count selector and Auto toggle through to `ScanSettings` immediately on set (both are plain `int`/`bool` writes, safe to cross threads without a lock), owns the pending cohort, and drives capture (`CaptureFromPipelineAsync`) and commit (`CommitCohortAsync`). `TileViewModel` wraps one `CohortTile` per grid tile; since `CohortTile` has no `INotifyPropertyChanged` and the UI is its only mutator after construction, the wrapper never re-derives state — it reflects `IsLowConfidence`, `State`, `DisplayName` and `DistanceText` straight off the tile, and calls the tile's own `ToggleExcluded`/`SetManually`/`Clear` before raising `Refresh()`. It never compares `ChosenDistance` to a threshold itself — that comparison lives entirely inside `CohortTile`. `CollectionViewModel` reads `ICollectionStore.ListAsync()` into `Rows` and wraps each registered `ICollectionExporter` in an `ExporterItem` for the picker; no per-format code lives in the view layer.

**Runs.** `RunStore` (issue #20) is the `ICollectionStore` Real mode commits to: it delegates to one `CsvCollectionStore` per run file and can be pointed at another file mid-session. A new run is named after the local time and its file and folder appear only at the first commit, so a launch with no scanning leaves nothing in Documents. `OpenAsync` reads the file before switching, so a Moxfield export throws and the current run stays open. Recent runs are a listing of the runs folder. It takes an `openStore` delegate rather than naming `CsvCollectionStore`, since only `AppComposition` may know concrete implementations. The window's File menu drives it, refuses every switch while a cohort is pending, and reports refusals and failures in a dismissible notice banner. Fakes mode has no `RunStore` (its store is in memory), so the run commands are disabled there.

**Type-ahead.** The "Set card manually…" `AutoCompleteBox` is wired in code-behind (`OnTypeAheadLoaded`) rather than XAML, because `AsyncPopulator` is a delegate-typed property XAML can't assign reliably. Settings: `MinimumPrefixLength = 2`, `MinimumPopulateDelay = 150 ms`, capped at 20 results, scanned via `Task.Run` (not `Task.Yield` — on the UI thread that resumes back on the UI thread, defeating the point). Matching is `OrdinalIgnoreCase` in two tiers — names starting with the typed text, then names containing it elsewhere — so "holding" still finds "Bag of Holding", ranked after any name that actually starts with it; within each tier, runners-up from `CohortTile.Candidates` are listed before the wider `IOracleCatalog.All` scan. `FilterMode` is set to `None`: the control's own default (`StartsWith`) would re-filter the populator's already-correct, already-ordered result against the raw typed text and silently drop every substring-elsewhere match. Without `MinimumPrefixLength`/`MinimumPopulateDelay`, `AutoCompleteBox`'s own defaults (`MinimumPrefixLength = 1`, `MinimumPopulateDelay = 0`) would scan the full ~33k-entry catalog synchronously on the UI thread on every keystroke. `OnTileTapped` also checks whether a tap's source has an `AutoCompleteBox` as a LOGICAL ancestor, so a click inside the box's own text field (which lives inside the tile's visual tree) doesn't also toggle the tile's X — `TileViewModel.IsTypeAheadOpen` alone can't gate this, since picking a dropdown entry closes the overlay before the click's `Tapped` event finishes bubbling. Arrow keys only move the dropdown's highlight: a pick happens when the dropdown closes with an entry selected (Enter or a click), never while it is open, and Escape picks nothing.

**`Fakes/`.** Three App-owned wrappers around the frozen `Core/Fakes` stubs — none edits the stubs themselves. `LayoutFollowingCardDetector` re-reads `ScanSettings.ExpectedCount` on every `Detect` call so switching the 1/3/9 selector at runtime actually changes what the next frame contains. `DemoCardIdentifier` cycles its wrapped `StubCardIdentifier`'s distance through three states (confident / low-confidence / Unresolved) per call, derived arithmetically from `ScanSettings.GoodDistance`/`OkDistance` so it holds no distance literal of its own. `DemoThresholds` is the one sanctioned exception to that rule — `GoodDistance = 100`, `OkDistance = 200`, the only distance literals anywhere in `LoreFetch.App`, exempt from plan item I4 — needed because Fakes mode has no real `thresholds.json` to load; without them every tile would default to Unresolved and the keyboard loop could capture but never commit anything. **`Fakes/` is Fakes-mode-only** — Real mode (packages I1–I3) loads the genuine values from the committed `ThresholdsFile` instead and never consults this folder for anything.

**`RealWebcamFrameSourceFactory`/`AlreadyFailedFrameSource`** (private to `AppComposition`). `WebcamFrameSourceFactory.CreateAsync` throws `FrameSourceException` synchronously when no usable camera is found — by design, so a bad negotiation surfaces at startup rather than from inside the enumerator. Composition happens *before* `MainWindow` exists, so letting that exception propagate there would crash the app instead of showing the `SourceFailed` banner A9 built. `RealWebcamFrameSourceFactory` catches it and hands back an `IFrameSource` whose `ReadAsync` re-throws the same exception the moment `IScanPipeline.RunAsync` evaluates it — which is inside that method's own `try`/`catch (FrameSourceException)` — so the existing mechanism fires exactly as it would for a camera that disconnects mid-session.

**`Diagnostics/`.** `DiagnosticsReporter` logs one `Diagnostics: …` line every 10 seconds: preview fps (frames actually blitted, counted in `OnRenderFrame`), pipeline fps (frames `FrameProcessed` raised, independent of whether the ~15 fps throttle actually rendered them), managed memory (`GC.GetTotalMemory`), process working set, and gen 0/1/2 collection counts. The two fps counters are deliberately separate `RateCounter` instances rather than one counter with two call sites — collapsing them would let "rendered fps" silently read the same as "received fps", masking exactly the choppy-preview regression this line exists to catch.

**Environment variables.**

- `LOREFETCH_MODE` — `real` (default, since package I3) or `fakes`, case-insensitive. Selects `CompositionMode`. An unrecognised value is logged as an error and falls back to `Fakes` — never to `Real` — so a typo is never the reason the app tries (and possibly fails) to open a camera or load a hash index.
- `LOREFETCH_COLLECTION` — Real mode only. A full path to a run file to open at startup, instead of starting a new run in `<Documents>/LoreFetch/Runs/`. Its containing directory is created if it doesn't already exist. Tests and replays set it so they never touch Documents.
- `LOREFETCH_FRAMES_DIR` — points the frame source (both modes) at a folder of your own images instead of the camera (Real) or the generated placeholder frames (Fakes); a missing or empty folder logs an error and falls back to generated placeholder frames rather than crashing — yes, even in Real mode, which is an unusual pairing but a deliberate, documented degrade-in-place — and a user-supplied folder is never deleted on shutdown (only the generated temp folder is). **Set this before running the app or its tests on a machine where the camera is in use for something else** — Real mode opens the webcam whenever this is unset.
- `LOREFETCH_SMOKE_EXIT_MS` — makes the app shut itself down after a fixed delay, for smoke-launch verification without a human closing the window.

**Failure modes, Real mode.** A missing or corrupt `data/index/cards.lfidx` or `data/index/thresholds.json` logs a critical error naming the path and exits with a non-zero code — never a silent fallback to Fakes. A camera that is not attached shows the ordinary `SourceFailed` banner instead (see `RealWebcamFrameSourceFactory` above) — the app stays up, the same as any other frame-source failure.
