# LoreFetch.App

The Avalonia desktop app: camera preview, capture/cohort UI, collection view and export picker. Owned by **Stream A** (worktree `stream-a`), which also owns `Core/Trigger/**` (the `IAutoCaptureTrigger` implementation) and `Tests/StreamA/**` — see [`../../docs/CONTRACTS.md`](../../docs/CONTRACTS.md#stream-boundaries).

## Dependencies

References `LoreFetch.Core` and `LoreFetch.Capture` (project references, both frozen at Stream 0). This project is the **composition root**: it is the only place that calls `ScanPipelineFactory.Create` and `IFrameSourceFactory.CreateAsync`, both frozen in `Core/Scanning`. It does not implement the wiring itself, and it does not reference OpenCvSharp — no contract type exposes one (see [`../../docs/CONTRACTS.md`](../../docs/CONTRACTS.md)), so the UI stream never writes CV code. Frames cross into the UI as `byte[]`/`CameraFrame`, converted to a single reused `WriteableBitmap`.

At integration, App wires the concrete `WebcamFrameSourceFactory` (stream C) — see the fixed name in [`../../docs/orchestration-plan.md`](../../docs/orchestration-plan.md) §4. Until then it runs against `Core/Fakes` (`FolderFrameSource` and friends).

Package I1 wires in the real collection store (`LoreFetch.Core.Collection.CsvCollectionStore`) and both real export adapters (`LoreFetch.Core.Export.NativeCsvExporter`, `LoreFetch.Core.Export.MoxfieldCsvExporter`) behind `CompositionMode.Real`. The frame source, detector, rectifier, identifier and catalog stay exactly as `CompositionMode.Fakes` composes them until I2 (hash index, detector, rectifier) and I3 (webcam) land.

## Stack pins and traps

Avalonia 12.1.2, `Avalonia.Controls.DataGrid` as a separate package, `CommunityToolkit.Mvvm`. See [`../../CLAUDE.md`](../../CLAUDE.md#stack-with-the-traps) for the version traps (12.0.x render-pass regression, `WriteableBitmap` allocation/`Lock()` disposal rules, xunit v3 requirement for headless tests).

## Testing

Unit-tested in `../../Tests/StreamA` (view-model logic, trigger state). Exercised end-to-end, via fakes, in `../../Tests/Integration`. UI rendering itself is verified manually, not headlessly — see [`../../docs/TESTING.md`](../../docs/TESTING.md#things-deliberately-not-tested-automatically).

## Internals

**Composition root.** `AppComposition.CreateAsync(CompositionMode, …)` is the only place that calls `IFrameSourceFactory.CreateAsync` and `ScanPipelineFactory.Create`. `CompositionMode` has two cases: `Fakes` wires the seven `Core/Fakes` implementations plus this stream's own `AutoCaptureTrigger`, wrapping two of the stubs — `LayoutFollowingCardDetector` over `StubCardDetector`, `DemoCardIdentifier` over `StubCardIdentifier` (see `Fakes/` below) — so the demo actually tracks the UI's own settings instead of freezing at whatever composition set once at startup. `Real` (package I1) shares that exact pipeline-piece wiring — `AppComposition.BuildFakesPipelinePieces` is the one place both modes build it from — but swaps in the real collection store (`CsvCollectionStore`) and both real export adapters (`NativeCsvExporter`, `MoxfieldCsvExporter`) in place of the stubs. The webcam and the hash index still slot in at I2/I3; nothing about `CompositionMode`'s shape has to change again when they land.

**Preview path.** `MainWindow` allocates exactly one `WriteableBitmap` for the life of the window (`EnsureBitmap`), reallocated only when the frame's dimensions change. Each pipeline callback (`OnFrameProcessed`, background thread) hands its bytes to `FrameHandoff` — a three-slot rotation, not one shared buffer — because the earlier single-buffer design let the UI thread convert from a *reference* to the same array the pipeline thread could still be overwriting, tearing frames (top of one frame, bottom of the next). `FrameHandoff` makes that impossible by construction: the producer's back slot is always distinct from whatever the consumer currently holds, so a write into a slot mid-read can't happen. `OnRenderFrame` (UI thread) takes the newest slot, converts it via `PixelConvert.ToBgra32`, locks the bitmap, copies, and disposes the lock **before** calling `InvalidateVisual()` — in that order, because the Skia backend only invalidates its cached `SKImage` snapshot on the lock's `Dispose()`, not on `InvalidateVisual()` itself. Rendering is throttled to ~15 fps and coalesced to at most one outstanding request; a frame landing inside the throttle interval used to be dropped silently, which left the last frame undrawn forever if the source then stalled — it's now deferred with a timer instead, so the newest frame still reaches the screen even if nothing else arrives.

**Overlay transform.** `FrameToControlTransform` maps a `CardQuad`'s frame-coordinate corners onto `PreviewImage`'s control coordinates, accounting for `Stretch="Uniform"` letterboxing: scale by the smaller of the two axis ratios, then centre the slack on whichever axis has it. It's a pure, directly-tested function rather than inline arithmetic in the render callback — getting the min/centring wrong silently misplaces every quad without ever throwing.

**View models.** `MainViewModel` is the window's `DataContext`: it writes the count selector and Auto toggle through to `ScanSettings` immediately on set (both are plain `int`/`bool` writes, safe to cross threads without a lock), owns the pending cohort, and drives capture (`CaptureFromPipelineAsync`) and commit (`CommitCohortAsync`). `TileViewModel` wraps one `CohortTile` per grid tile; since `CohortTile` has no `INotifyPropertyChanged` and the UI is its only mutator after construction, the wrapper never re-derives state — it reflects `IsLowConfidence`, `State`, `DisplayName` and `DistanceText` straight off the tile, and calls the tile's own `ToggleExcluded`/`SetManually`/`Clear` before raising `Refresh()`. It never compares `ChosenDistance` to a threshold itself — that comparison lives entirely inside `CohortTile`. `CollectionViewModel` reads `ICollectionStore.ListAsync()` into `Rows` and wraps each registered `ICollectionExporter` in an `ExporterItem` for the picker; no per-format code lives in the view layer.

**Type-ahead.** The "Set card manually…" `AutoCompleteBox` is wired in code-behind (`OnTypeAheadLoaded`) rather than XAML, because `AsyncPopulator` is a delegate-typed property XAML can't assign reliably. Settings: `MinimumPrefixLength = 2`, `MinimumPopulateDelay = 150 ms`, ordinal `StartsWith` matching, capped at 20 results, with runners-up from `CohortTile.Candidates` listed before the wider `IOracleCatalog.All` scan. Without these, `AutoCompleteBox`'s own defaults (`MinimumPrefixLength = 1`, `MinimumPopulateDelay = 0`) would scan the full ~33k-entry catalog synchronously on the UI thread on every keystroke.

**`Fakes/`.** Three App-owned wrappers around the frozen `Core/Fakes` stubs — none edits the stubs themselves. `LayoutFollowingCardDetector` re-reads `ScanSettings.ExpectedCount` on every `Detect` call so switching the 1/3/9 selector at runtime actually changes what the next frame contains. `DemoCardIdentifier` cycles its wrapped `StubCardIdentifier`'s distance through three states (confident / low-confidence / Unresolved) per call, derived arithmetically from `ScanSettings.GoodDistance`/`OkDistance` so it holds no distance literal of its own. `DemoThresholds` is the one sanctioned exception to that rule — `GoodDistance = 100`, `OkDistance = 200`, the only distance literals anywhere in `LoreFetch.App`, exempt from plan item I4 — needed because Fakes mode has no real `thresholds.json` to load; without them every tile would default to Unresolved and the keyboard loop could capture but never commit anything. Real mode (integration) loads the genuine values from `ThresholdsFile` instead and never consults this class.

**`Diagnostics/`.** `DiagnosticsReporter` logs one `Diagnostics: …` line every 10 seconds: preview fps (frames actually blitted, counted in `OnRenderFrame`), pipeline fps (frames `FrameProcessed` raised, independent of whether the ~15 fps throttle actually rendered them), managed memory (`GC.GetTotalMemory`), process working set, and gen 0/1/2 collection counts. The two fps counters are deliberately separate `RateCounter` instances rather than one counter with two call sites — collapsing them would let "rendered fps" silently read the same as "received fps", masking exactly the choppy-preview regression this line exists to catch.

**Environment variables.**

- `LOREFETCH_MODE` — `fakes` (default) or `real`, case-insensitive. Selects `CompositionMode`. This package (I1) keeps the default at `Fakes`; I3 flips it once the camera is wired. An unrecognised value is logged as an error and falls back to `Fakes` — a typo here is never the reason the app won't start.
- `LOREFETCH_COLLECTION` — Real mode only. A full path to the collection CSV file. Defaults to `<Documents>/LoreFetch/collection.csv` when unset; either way the containing directory is created if it doesn't already exist.
- `LOREFETCH_FRAMES_DIR` — points the frame source (both modes) at a folder of your own images instead of the generated placeholder frames; a missing or empty folder logs an error and falls back rather than crashing, and a user-supplied folder is never deleted on shutdown (only the generated temp folder is).
- `LOREFETCH_SMOKE_EXIT_MS` — makes the app shut itself down after a fixed delay, for smoke-launch verification without a human closing the window.
